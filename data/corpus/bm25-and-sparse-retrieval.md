# BM25 and Sparse Retrieval

BM25 (Best Matching 25) is a ranking function used to score how well a document matches a query, based on the query terms that literally appear in the document — it is a "sparse" or lexical method, in contrast to "dense" methods that compare learned embedding vectors. BM25 is a refinement of the older TF-IDF (term frequency–inverse document frequency) family: it scores a document highly if it contains the query's terms frequently (term frequency), especially if those terms are rare across the whole corpus (inverse document frequency, which downweights common words like "the" that appear everywhere and carry little discriminative signal).

BM25 improves on plain TF-IDF with two adjustments. First, it saturates term frequency: the tenth occurrence of a query term in a document adds much less score than the second occurrence, controlled by a parameter k1, reflecting the intuition that a document mentioning a term ten times is not necessarily ten times more relevant than one mentioning it once. Second, it normalizes for document length using a parameter b: without this, longer documents would score higher simply by containing more words and thus more chances to match query terms, so BM25 penalizes term matches in documents that are much longer than the corpus average.

Sparse lexical retrieval has properties that complement dense semantic retrieval. It matches exact tokens, so it excels at queries containing specific identifiers, codes, product names, acronyms, or rare technical terms that an embedding model may not have learned to represent distinctly, since embedding models are trained on general semantic similarity and can conflate rare terms with semantically similar but distinct ones. Sparse retrieval also requires no model inference at index or query time (beyond tokenization), making it cheap, fast, and fully interpretable — you can always point to exactly which terms matched. Its weakness is the flip side of dense retrieval's strength: it cannot match a query to a relevant document that uses different words for the same concept (a query for "car" will not match a document that only says "automobile" unless the tokenizer or an explicit synonym list bridges the gap).

In practice, BM25 remains a strong and surprisingly competitive baseline in information retrieval benchmarks, and it is common for production hybrid search systems to run BM25 and dense vector search in parallel over the same corpus and combine their rankings, because the two methods tend to make different mistakes — errors are not perfectly correlated, so combining them recovers relevant results that either method alone would miss.
