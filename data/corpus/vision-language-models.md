# Vision-Language Models

Vision-language models (VLMs) extend the capabilities of large language models to accept images as input alongside text, enabling tasks such as visual question answering, image captioning, document and diagram understanding, and grounding language in visual detail. Most modern VLMs share a common architectural pattern: a pretrained vision encoder converts an image into a sequence of visual features, a connector module projects those features into the same embedding space the language model expects, and the language model then processes the combined sequence of visual and text tokens using the same Transformer machinery used for text alone.

The vision encoder is typically a Vision Transformer (ViT), which treats an image as a grid of fixed-size patches (for example 16x16 pixels), linearly projects each patch into an embedding, and processes the sequence of patch embeddings with standard Transformer self-attention layers — the same way a text Transformer processes a sequence of word/token embeddings. Encoders like CLIP's vision tower are popular choices because they were pretrained with a contrastive objective against paired text captions, meaning their visual features already carry some alignment with language semantics before ever being connected to an LLM.

The connector module is where architectures diverge. A simple linear projection (or a small MLP) maps each patch embedding directly into the LLM's embedding dimension, preserving one token per image patch — simple and information-preserving, but it can produce a large number of visual tokens for a high-resolution image, consuming a significant fraction of the LLM's context window. Resampler-based connectors (such as the Q-Former used in BLIP-2, or the perceiver-resampler pattern) instead use a small set of learned query vectors that cross-attend into the full set of patch features and compress them down to a fixed, much smaller number of tokens regardless of image resolution, trading some spatial detail for a far more context-efficient representation.

Training a VLM typically proceeds in stages: first, only the connector module is trained (with the vision encoder and LLM both frozen) on large-scale image-caption pairs, to teach the connector to translate visual features into something the frozen LLM can already interpret; then, some or all of the LLM (and sometimes the vision encoder) is unfrozen and fine-tuned jointly on instruction-following, multi-turn visual dialogue, and task-specific data, so the model learns to actually follow visual instructions rather than just caption images.

A well-documented failure mode in VLMs is "visual hallucination" — describing objects, text, or relationships that are not actually present in the image — which parallels textual hallucination in LLMs and stems from a similar cause: the model is optimized to produce fluent, plausible descriptions, and in the absence of strong visual evidence for a specific detail, it can fall back on generic priors about what usually appears in similar-looking scenes (for example, assuming a kitchen scene contains a stove even if the image happens to crop it out). This is a particular concern for document and diagram understanding, where an incorrect but plausible-looking transcription of a label or a value is much harder for a downstream user to catch than an obviously wrong description of a photo.
