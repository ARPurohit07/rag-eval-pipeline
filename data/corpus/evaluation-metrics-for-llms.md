# Evaluation Metrics for LLMs and RAG Systems

Evaluating a language model or a RAG system well requires different metrics depending on what stage of the pipeline is being measured, because a strong final answer requires several independent things to go right, and a single end-to-end score cannot tell you which one failed.

Classic NLP generation metrics like BLEU and ROUGE compare a generated text against a reference text based on overlapping n-grams (contiguous sequences of words). They are cheap to compute and require no model calls, but they penalize valid paraphrases that use different wording than the reference and reward superficial word overlap even when the meaning is wrong, which makes them a poor fit for evaluating open-ended, free-form answers from modern LLMs — two answers can be equally correct and share almost no n-grams, or share many n-grams while differing in a critical fact.

LLM-as-judge evaluation instead uses a (typically strong) language model to score or compare outputs according to a rubric described in a prompt, which better captures semantic correctness and nuanced quality judgments than n-gram overlap, at the cost of being more expensive, slower, non-deterministic, and subject to the judge model's own biases (for example, some judge models have been shown to systematically prefer longer answers, or the first answer presented in a pairwise comparison, independent of actual quality). Using a stronger, ideally different, model as the judge than the one being evaluated, and validating judge scores against a sample of human ratings, are common mitigations for judge bias.

For RAG specifically, the RAGAS framework decomposes evaluation into metrics that isolate retrieval quality from generation quality, since a RAG system can fail at either stage independently. Context precision measures what fraction of the retrieved chunks are actually relevant to the question, penalizing a retriever that pads its results with irrelevant passages. Context recall measures whether the retrieved chunks, taken together, contain all the information present in a reference (ground-truth) answer, penalizing a retriever that missed something necessary. Faithfulness measures whether every claim in the generated answer is actually supported by the retrieved context, by decomposing the answer into individual claims and checking each one against the context — this specifically targets hallucination that happens even when relevant context was retrieved. Answer relevancy measures whether the generated answer actually addresses the question asked, independent of whether it is factually correct, catching cases where a model produces a well-supported but off-topic or evasive response.

Because context precision and recall depend on knowing which chunks are truly relevant, and faithfulness/answer relevancy require judging semantic entailment, most RAGAS-style metrics are themselves computed by prompting an LLM judge with a decomposed, structured task (such as "list the individual factual claims in this answer") rather than by simple string matching, which means the reliability of these metrics is itself bounded by the judge model's own reasoning quality — a weak or inconsistent judge model will produce noisy metric scores, which is why the choice of judge model for an evaluation pipeline matters as much as the choice of the metrics themselves.
