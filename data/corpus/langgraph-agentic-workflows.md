# LangGraph and Agentic Workflows

LangGraph is a library for building applications as explicit state machines (graphs) of nodes and edges, where each node is typically a function or an LLM call that reads and updates a shared state object, and edges determine what runs next. It was built by the LangChain team specifically to address a limitation of simpler "chain" abstractions (a fixed, linear sequence of steps): many real applications, especially agentic ones, need loops, conditional branching, and the ability to revisit earlier steps based on intermediate results, none of which a straight-line chain can express cleanly.

The central abstraction is the state graph: a developer defines a state schema (the shape of the data that flows through the graph — for example, a conversation history, a set of retrieved documents, a scratchpad of intermediate reasoning), adds nodes that each take the current state and return updates to it, and connects nodes with edges that can be conditional — a routing function inspects the current state and decides which node to execute next. This makes control flow explicit and inspectable: rather than an LLM implicitly deciding what to do next hidden inside a single large prompt, the possible transitions are declared upfront as edges in a graph, even if the routing decision at a particular edge is itself made by an LLM call.

This structure is well suited to agentic patterns where an LLM needs to take multiple actions and observe their results before responding: a node calls the LLM with the current state and a set of available tools, the LLM's response either contains a final answer or a request to call a specific tool, a conditional edge routes to a "tool execution" node if a tool was requested, that node runs the tool and appends its result to the state, and control loops back to the LLM node so it can decide what to do next given the new information — continuing until the LLM produces a final answer instead of a tool call. This explicit loop is what lets an agent perform multi-step tasks like "search for X, then use what you found to look up Y, then summarize both" without that entire procedure being hardcoded in advance.

LangGraph also provides built-in support for persistence (checkpointing the state graph so a long-running or multi-turn interaction can be paused and resumed later, potentially across process restarts) and for human-in-the-loop interrupts (a graph can pause execution at a designated node and wait for external approval or input before continuing — useful for agentic workflows where a proposed action, like sending an email or executing a database write, should be reviewed by a human before it actually happens). Both of these are naturally expressed as graph-level concerns — pausing at a node boundary and resuming from saved state — in a way that is harder to retrofit onto an implicit, single-prompt agent loop.

Compared to simpler single-prompt "ReAct"-style agents (where the tool-use loop lives entirely inside one long, repeatedly-appended prompt), an explicit graph makes the set of possible states and transitions easier to reason about, test, and debug — a developer can unit-test an individual node in isolation, or visualize the graph structure to audit what paths an agent could possibly take — at the cost of more upfront structure than simply writing a single prompt and letting the model figure out control flow implicitly.
