# Hybrid Search and Re-ranking

Hybrid search combines a sparse lexical method (typically BM25) with a dense semantic method (vector similarity over embeddings) into a single ranked result list, on the premise that the two methods have complementary strengths: BM25 is precise about exact terms but blind to paraphrase, while dense retrieval understands paraphrase and meaning but can miss queries that hinge on a specific rare term or identifier.

The central challenge in hybrid search is that BM25 scores and cosine-similarity scores live on different, incomparable scales — a BM25 score might range from 0 to 30 depending on the corpus, while cosine similarity is bounded between -1 and 1 — so the two rankings cannot simply be summed. Reciprocal Rank Fusion (RRF) sidesteps this by ignoring the raw scores entirely and combining rankings instead: for each document, RRF computes 1 / (k + rank) in each ranked list it appears in (where k is a small constant, commonly 60, that dampens the influence of very low ranks) and sums this across lists. A document ranked highly by either method gets a large contribution; a document that both methods agree is relevant gets contributions from both lists and rises to the top. RRF requires no score normalization and no tuned weights, which makes it a robust default, though a weighted linear combination of min-max-normalized scores is a common alternative when there is enough labeled data to tune the weights.

Re-ranking is a separate, typically later stage: after an initial retriever (BM25, dense, or hybrid) narrows a large corpus down to a small candidate set — say, the top 50 or 100 — a more expensive model re-scores just those candidates against the query and re-sorts them, before the top few are passed to the generator. Re-rankers are usually cross-encoders: unlike a bi-encoder (used for the initial embedding-based retrieval), which encodes the query and each document independently into separate vectors and compares them afterward, a cross-encoder feeds the query and a candidate document into the model together, so it can directly attend between query and document tokens and produce a much more accurate relevance score. Cross-encoders are too slow to run over an entire corpus (they require one full forward pass per query-document pair), which is exactly why they are reserved for re-ranking a short candidate list rather than for first-stage retrieval.

The typical production pipeline is therefore staged: a cheap, high-recall first stage (BM25 and/or dense retrieval, possibly fused with RRF) casts a wide net over the whole corpus, and a slower, high-precision second stage (cross-encoder re-ranking) refines the top candidates down to the small number of chunks that actually get passed into the generator's context window. This staging exists because running the accurate-but-slow method over the entire corpus for every query would be too expensive, while running only the cheap-but-less-precise method risks passing lower-quality context to the generator.
