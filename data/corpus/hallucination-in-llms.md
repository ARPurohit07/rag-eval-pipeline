# Hallucination in Large Language Models

Hallucination refers to a language model generating content that is fluent and confident-sounding but factually incorrect, unsupported by any source, or internally inconsistent. It is a direct consequence of how these models are trained and how they generate text: a language model is fundamentally a next-token predictor optimized to produce plausible continuations, not a database with a built-in notion of "I don't actually know this," so when a prompt pushes the model toward a topic it has weak or no reliable knowledge about, it will typically still produce a fluent-sounding answer rather than an explicit admission of uncertainty, because fluent continuation is what the training objective rewards.

It is useful to distinguish two broad categories. Intrinsic hallucination happens when a model contradicts information that was actually given to it in its own context — for example, summarizing a document but inserting a detail the document never stated, or contradicting an instruction given earlier in the same conversation. Extrinsic hallucination happens when a model asserts something about the world that cannot be verified against, or is contradicted by, its provided context or reliable external sources — this is the more commonly discussed form, and it is what RAG's faithfulness metric specifically targets: does every claim in the answer trace back to something actually present in the retrieved context, or did the model add unsupported claims from its parametric memory?

Several factors increase hallucination risk. Long-tail or rarely-seen facts during pretraining are more likely to be misremembered or fabricated than well-represented, frequently-repeated facts. Long context windows can suffer from a "lost in the middle" effect, where information placed in the middle of a very long prompt is used less reliably than information near the beginning or end, increasing the chance the model ignores relevant retrieved context it was actually given. Ambiguous or underspecified questions invite the model to guess at the user's intent rather than asking for clarification. And instruction-tuned/RLHF'd models can develop a tendency toward sycophancy — producing an answer the model infers the user wants to hear, even when that conflicts with the evidence in context — which is a subtler form of unfaithfulness than outright factual fabrication.

Mitigations operate at different points in a system. Retrieval augmentation reduces hallucination by giving the model something concrete to ground its answer in, but does not eliminate it, because a model can still ignore retrieved context or embellish beyond what it supports; explicit prompting to "only answer using the provided context, and say you don't know if the answer isn't present" measurably reduces (but does not fully prevent) ungrounded generation. Citation-generation, where the model is required to attribute specific claims to specific retrieved passages, makes unsupported claims easier for a human (or an automated faithfulness check) to spot, because a claim with no attached citation is a clear signal to scrutinize. Post-hoc verification — running a second pass, often another LLM call, that checks each claim in a draft answer against the source context and flags or removes unsupported ones — trades extra latency and cost for a direct check on faithfulness, and is essentially the same idea RAGAS's faithfulness metric formalizes for offline evaluation rather than live serving.
