# Context Windows and Long-Context Models

A language model's context window is the maximum number of tokens (a token being roughly a word-piece — a whole word, part of a word, or punctuation) it can process in a single forward pass, spanning both the input prompt and the tokens generated so far. Early Transformer LLMs had context windows of a few thousand tokens; modern frontier models commonly support context windows of 100,000 to over a million tokens, driven by both architectural changes and systems-level optimization, since naive self-attention's quadratic cost in sequence length made very long contexts computationally impractical in the original Transformer formulation.

Extending context length has required progress on several fronts. Positional encoding schemes that generalize better to lengths unseen during training — such as RoPE (rotary position embeddings) combined with scaling techniques that stretch or reinterpret position indices at inference time — let a model trained at one context length process meaningfully longer sequences without retraining from scratch, though usually with some quality degradation the further the extrapolation goes. Efficient attention implementations, especially FlashAttention, reduce the memory bandwidth cost of computing exact attention by restructuring the computation to avoid materializing the full attention matrix in slow GPU memory, which does not change attention's quadratic compute cost but substantially reduces its practical memory and wall-clock cost. And architectural variants such as sliding-window attention (each token only attends to a fixed-size local window of nearby tokens in most layers) or various sparse/linear attention schemes trade some ability to model arbitrary long-range interactions for sub-quadratic (or even linear) scaling in sequence length.

Having a large context window does not guarantee a model uses all of it equally well. Empirically, many long-context models exhibit a "lost in the middle" pattern: retrieval accuracy for a fact placed near the beginning or end of a long context is measurably higher than for the same fact placed in the middle, even though the fact is technically present and attention in principle allows access to any position. This means simply having a large enough context window to fit all potentially relevant documents is not sufficient for a system to reliably use all of them — a RAG system with poor retrieval that dumps twenty marginally-relevant chunks into a long context is not necessarily better, and can be worse, than one that retrieves three highly-relevant chunks, because the model may fail to weight the genuinely relevant one appropriately amid the noise.

This is one of the more important practical relationships between RAG and long-context models: a bigger context window changes how many retrieved chunks can fit, but it does not remove the value of good retrieval and ranking — it is generally more reliable to retrieve fewer, more precisely relevant chunks (helped by good chunking, hybrid search, and re-ranking) than to rely on a large context window to compensate for imprecise retrieval by including many chunks and hoping the model finds the right one.
